没有自动查找、自动创建或默认资产回退。缺引用、真实表缺失、适配失败、配置错误或源读取异常时，初始化报告不可用，目录输出null，依赖方应停止自己的相关工作。合法的八个零行表可形成可用空目录，查询不到具体对话另返回false；可用不等于有业务内容、素材全部可加载或场景已校验。

数据只经原 `NarrativeDataAdapter.TryCreate` 和Catalog公开查询取得。Catalog内部既有ICatalogSource在编辑器/开发构建使用ScriptableObject数据，`CK01_ENCRYPTED_DATA && !UNITY_EDITOR && !DEVELOPMENT_BUILD`时使用加密包策略；本卡不修改或替换它。`SourceKind`返回本次初始化实际源标识；即使加密包读取失败，也不会转去读SO、CSV、Resources或伪造空表。八表发布/Prefab引用接入仍是V013-11的后续范围，本卡不声称发布包已可用。

可通过 `Configure(config, catalog)` 改绑定，再 `Initialize()` 显式读取；也可由首次 `IsAvailable`、`Diagnostics`、`SourceKind`、查询调用触发初始化。目录是Adapter的只读快照，同一次初始化复用；数据源重载/同Catalog内容变更后，使用方显式调用Initialize刷新。失败结果也缓存，不会在每帧属性读取中不断重试。配置的原Changed事件会使派生缓存失效，下次查询重新初始化；代码修改演出配置仍沿原 `NotifyChanged()` 约定通知，或显式Initialize。绑定变化、启停会重置缓存；停用/销毁退订配置事件。没有Update/定时扫描或新全局单例。

初始化Diagnostics是只读字符串清单，`MISSING_CONFIG`、`MISSING_CATALOG`、`DISABLED`、`CONFIG`、`DATA`、`READ_FAILED`分别表示缺引用、停用、原配置/适配诊断或异常类型与原因；失败会写一条带组件名称的Unity警告。一次成功不保证后续所有id存在。查询缺id等诊断经out参数返回，原Resolver允许的回退/override警告保留在resolution的ConfigurationDiagnostics/OverrideDiagnostics或Diagnostics中，不改变原成功语义。读取/解析异常会使接入点不可用并清除旧目录，待明确刷新或改绑定恢复。

本组件没有画面效果、调试按钮或数值滑杆。实际Managers挂载、引用保存、MonoScript/原生加载和发布数据验证留后续任务；本次离线验证不能代签这些结果。离线保留宿主的JsonUtility序列化stub不会判断真实配置编辑变化，因此事件用例明确投递原Changed委托，原生NotifyChanged序列化检测未在本卡验证。
