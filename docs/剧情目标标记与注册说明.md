角色 id 必须以 `chr_` 开头，基础 id 只含小写 ASCII 字母、数字与下划线，长度≤40；显式实例后缀为十进制且至少 2（`#02` 保留原文并与 `#2` 区分）。锚点同用小写 id 规则但不强制 `chr_`。角色和锚点 id 使用既有 NarrativeCommandTargetParser 规则。示例 `actor:chr_vendor`、`actor:chr_vendor#2`、`anchor:door`、`player`；不要把整段目标串填入标记 id 字段。脚底位置与后续 GroundSpace 距离计算由消费者处理，本组件不改主角或镜头。

注册表启用时扫描本场景的根及其子树，只收集处于启用状态的标记；标记先启用、注册表后出现也可以收集。之后标记启用/停用/销毁自动登记或注销，注册表停用清空清单，再启用重新收集。跨 additive 场景的同名 id 互不混淆。通过脚本改 id 使用 `ConfigureId(string)`，它会注销旧登记再登记新 id；运行中直接改私有序列化字段不作为支持的即时配置入口，可停用再启用刷新。

同类重复 id 会产生 `DUPLICATE_ACTOR` / `DUPLICATE_ANCHOR` 警告；查找使用实际最先登记且仍有效的对象。移除该对象后，仍登记的下一个重复对象可被找到。再次启用的对象按新的登记顺序排在后面。场景首次扫描顺序由 Unity 的根/子树返回顺序决定，不用对象名称挑赢家；正式配置应消除重复。角色与锚点属于独立命名空间。

API：`TryGetActor(id, out Transform)`、`TryGetAnchorPosition(id, out Vector3)`、`TryGetPlayer(out Transform)`、`TryResolve(targetText, out Transform)`。失败返回 false，out 为 null 或默认 Vector3，并输出带本场景名的诊断；调用方必须检查 bool。非法 id/目标分别是 `INVALID_ID` / `INVALID_TARGET`，不存在分别是 `MISSING_ACTOR` / `MISSING_ANCHOR` / `MISSING_PLAYER`。不要把失败的默认坐标当作有效锚点。Player 的对象必须处于本场景且激活，代码接线可用 `ConfigurePlayer(Transform)`。

没有逐帧扫描。初始化/标记启停会扫描场景或现有注册表，查找按登记顺序遍历本场景小清单。需要把已登记对象移到另一个 Scene 时，先停用标记，迁移后再启用；不支持静默迁移后立即把旧登记当新场景登记。

离线验证通过也不代表 Unity 的实际回调顺序或场景接线完成；AI563已完成本场景/player原生接线，运行回调/行为仍由后续适用任务验收。此组件没有视觉参数或画面效果，人工视觉说明不适用。
