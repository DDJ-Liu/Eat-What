## 导表按文件名解析

现行事实：`SpriteLookupPolicy.Resolve`会Trim首尾空白，拒绝路径/扩展名；`DataTableImportService.FindExactSpritePaths`在上述合法目录用`AssetDatabase.FindAssets(... t:Sprite)`获取候选，再以`Path.GetFileNameWithoutExtension`及`StringComparison.Ordinal`做区分大小写的完整相等判断，去除重复路径。`ResolveSprite`加载唯一路径的Sprite，找不到、多路径同名或无法加载都会warning并使用既有统一占位；空字段不应当被自动填入业务资源名。不是取搜索结果第一项，也不是运行时遍历文件系统。

待确认后建议这样扩展到新三类字段：

- 后续获批工具以可配置、按类型登记的搜索根接入上表正式目录及相应占位目录，保持完整基名、类型与大小写精确匹配。两类Sprite建议共用唯一基名；同一类型的所有已启用目录先合并候选，再判断唯一，不通过目录顺序或文件排序消歧。不要自动扫描全Assets，也不要改旧Cooking清单/查询行为来偷接新目录。
- 立绘/CG须是可按资产路径加载的Sprite。现契约不是按图集子Sprite显示名索引；多图切片、图集子资产或只有Texture但未导成Sprite的素材先列为待处理，不猜子图，不通过改名掩盖类型问题。PNG只是建议交付格式，不在本卡强改现成品格式。
- 形象按约定根查找`.prefab`，精确比较无扩展名文件基名，唯一且可作为Prefab加载才绑定序列化引用。找不到、类型不符或多结果都warning、不阻断导表，不任取一个；未解析的引用保持未解析/空引用并交对应检查处理，不创造新的运行时按名搜索补救。是否显式使用上表占位Prefab由获批资产/配置决定，留空语义保持Schema共同约定B。
- 导表输出绑定序列化引用；运行期读生成目录/发布数据源已导出的引用，不再按名字查找。Schema关于新增`*_sprite`/`*_prefab`引用进入正式导出与发布读取路径的要求继续有效，不能把Editor查到一次等同发布完成。本卡不实现或运行该链。

## 两种用户交付流程

### 用户直接放入约定目录

1. 本方案的三类最终路径和占位安排已确认，后续先审定具体资产清单。先在根`美术资产/`同步区识别/比对的既有项目规则仍适用；用户明确选择直接放入工程时，逐文件使用已审定的正式目标，不经未经批准的Assets中转目录。
2. 用户按审定清单把新成品放到相应正式目录，保留约定基名。若是工程内已有资产，使用下一种迁移流程，避免操作系统搬移丢失GUID。Prefab及外部贴图、材质、动画等依赖一并列清，不只交一个壳文件。
3. 后续被授权的引擎/数据操作核对Importer、Sprite/Prefab类型、GUID、重复基名和已有引用，再导表绑定。修改已有非空单元格仍须用户明确授权；用户自己完成的配置按来源忠实导出，不倒灌旧CSV。
4. 交付实际路径/名称/GUID、导表引用和warning清单；素材不符或源文件漂移时先更新逐文件差异，不能把用户放入文件等同场景配置或视觉验收完成。

### 用户提供现路径，由开发端迁移

1. 用户提供实际源路径及用途；开发端先只读给出逐文件源/哈希、现工程资产/GUID/引用、建议最终路径和名称、复用/新增/替换/暂缓、备份与回退。用途或身份不明的资源暂缓。原图相同优先复用，不能为统一目录复制出第二份同名身份。
2. 由用户审阅具体映射和引用影响后才执行。保留已有成品文件名；确需改名时连同所有受影响字段和引用一起审定，不自动改非空配表、覆盖同名文件或删旧资产。如果同图应保留在既有目录，单独审定是否把精确现目录纳入该类搜索根，不擅自扩大搜索范围。
3. 工程内迁移通过获批Unity车道使用`AssetDatabase.MoveAsset`保GUID，不能把`.meta`单独重建或与文件拆开搬移；外部文件按审定目录导入，Prefab依赖也逐项核对。任一目标已存在或内容漂移先停止该项，保留源与备份并报告差异。
4. 后续检查实际新路径、原GUID及引用、Importer和导表结果，必要场景/表现由另获批任务处理。回退也以已保全的映射/GUID和用户未保存成果为边界，不能覆盖未知修改。
