### 运行时读取与 ENGINE 接线

`StreetConfigs.Current` 在绑定前为 `null`；绑定后只读地返回四个资产和两项场景引用。属性赋不同值、Play 中资产 Inspector 真正改值后的 `OnValidate`、或替换绑定来源会触发 `StreetConfigs.Changed`；重复同值/重复绑定不触发。`Unbind` 取消四资产事件订阅并发一次通知，重复取消不触发。消费者应在启用时订阅、停用时取消订阅；接收通知后重新读 `Current`，不可缓存旧资产来源。离线测试覆盖这些方法与回调；真实 Editor Inspector 时序仍待 ENGINE 窗口核验。配置资产字段不直接驱动角色移动或相机。

ENGINE 在本逻辑卡窗口 V② 通过 Editor 正常创建下列四个资产（含 Unity 生成的 `.meta`），核默认值和可加载：`Assets/Settings/Street/DepthScaleConfig.asset`、`CameraModeConfig.asset`、`CameraFollowConfig.asset`、`SceneBoundsConfig.asset`。把 `StreetConfigBinder` 挂在**现有** Street 入口对象，分别填写 Inspector 的 **Depth Scale Config**、**Camera Mode Config**、**Camera Follow Config**、**Scene Bounds Config**，并把场景水平基准线 Transform 填到 **Ground Line**、相机 Confiner 用 Collider2D 填到 **Camera Bounds**；不另建单例场景对象。Play 中核 `Current` 可读、改不同值通知一次、同值不通知、换绑定来源后旧资产不再通知、离开场景时解绑。当前 CODE 未创建这些资产或改场景，四资产可加载与原生 Inspector 结果仍未验收。

CFG阶段原七个预留类型中，`CameraInterestConfig`现由F02仅补本地SafeZoneWidth；其余 `SceneTransitionConfig`、`CinematicCameraConfig`、`CameraEffectsConfig`、`OcclusionConfig`、`SceneConfig`、`RoomCameraOverride`仍为空类型，不冒相应功能。W-04从`Current.DepthScale`读DEPTH/FOCUS，W-01/F-01已在源码接消费；正式资产、场景行为及最终值/观感仍须ENGINE与人工验收。

## W-04 地面距离与跟随点

两项输入都以**角色脚底的世界坐标**为基准，调用方明确提供脚底位置；不从 Sprite/Renderer 包围盒或角色身体中心推断。它们是不同的数值：地面距离用于半径/距离判定，FOCUS 跟随点用于镜头跟随与后续遮挡圆心。

| E2 参数／单位 | 实际函数或配置字段 | 挂载点 | 调整方法与计算含义 |
| --- | --- | --- | --- |
| `groundDist`／u | Toolkit `GroundSpaceMath.GroundDistance(Vector3 a, Vector3 b, float depth)`；LongLoop `GroundSpace.GroundDistance(Vector3 footA, Vector3 footB)` | Toolkit 是无状态纯函数；LongLoop 从当前 `StreetConfigs.Current.DepthScale.Depth` 取值 | `sqrt(dx²+(dy/DEPTH)²)`，只取世界 X/Y，忽略 Z。DEPTH=1 为平面欧氏距离，预设0.35使同样纵向位移在距离判定中更大。用于后续兴趣点、对话触发、遮挡范围判定；当前没有接具体消费方。 |
| `DEPTH`／0.35／无量纲 | `DepthScaleConfig.DEPTH`；运行时 `Depth` | `DepthScaleConfig` 资产 | 在资产 Inspector 修改 **DEPTH**；`GroundSpace.GroundDistance` 每次调用读取当前值，改值/换绑即时用于下一次计算。必须是有限正数；0、负数、NaN/∞ 显式拒绝，不静默代默认值。 |

ENGINE 后续在实际玩家结构中确认脚底锚点，基于 `GroundSpace.FollowPoint(footWorldPosition)` 驱动或摆放 FollowPoint 子节点，并将相机 Follow 引用指向该节点；同一脚底位置用于地面距离调用，不在多个组件各自猜中心。节点身份、场景绑定与画面效果要在 Editor/Play 中核实。本 CODE 段只提供函数与配置消费接口，没有创建节点、改相机或改变角色运动。W-01/F-01 可调用上述两个 LongLoop 函数，或在无需配置绑定的纯规则中显式传 DEPTH 给 Toolkit 函数；后续仍须按用途接入和原生验证。

## W-01 可行走区域与四向移动

`LongLoopPlayerController` 已读 `IGameInput.Horizontal/Vertical`。有效 `WalkArea` 中每轴输入单独钳到 −1～+1，世界 XY 每秒位移为 `(Horizontal, Vertical × Vertical Speed Factor_TUNE) × Move Speed_TUNE`；斜向不归一化，不借用 `DEPTH` 改写速度。Y 正向上、负向下；Transform 路径保留原 Z，Rigidbody2D 路径使用 `MovePosition`。`IsMoving` 对可行区域内的纵向运动报行走，纯纵向输入不改变左右朝向；Stop、失焦、暂停和组件禁用清两轴控制输入。

| 同组件 → **Walk Area**／场景引用 | `walkArea` 初值空 | 指向场景中的 `WalkArea_TUNE` 组件后启用二维投影；空引用、组件禁用或没有有效多边形时回退旧 X 边界，Y 保持原值。 |
| `WalkArea_TUNE` 对象的 **Walk Area** → **Regions**／`PolygonCollider2D` 数组 | `regions` 初值空 | 可放一个或多个启用的多边形；包含多个 path 的单个 Collider 也可用。有效区域按并集处理，区域内不改点，越界目标投影到距离最近的可行边/角。增大形状扩展可走范围，缩小形状收窄；禁用某个 Collider 会从并集中移除它。多边形可移动、旋转、缩放，按世界 XY 生效。 |
| 同一玩家组件的 **Boundary L_TUNE / Boundary R_TUNE** 与旧数值边界 | `boundaryL_TUNE`、`boundaryR_TUNE`，或 `useHorizontalBounds/minX/maxX` | 仅无有效 `WalkArea` 时作为 X 回退。两个 Transform 的左右顺序仍自动排序；纵向不会因空区域无界移动。 |
| 同组件的 **Freeze Vertical Rigidbody Position**／开关 | `freezeVerticalRigidbodyPosition` 默认 true | 无有效区域时保持原有本控制器 Y 冻结；有效二维区域时释放本控制器增加的 Y 冻结。外部原有 Y 冻结仍保持，不能靠 Walk Area 解除；此时纵向移动回退。未知运行时约束变更不会由本控制器覆盖。 |

沿边斜向移动时，外向分量被投影限制，切向分量继续推进；凹角按最近边投影。`WalkArea` 使用物理多边形当前世界变换，配置人员应在 Editor 检查多边形点、多个 path 及禁用状态；不把碰撞器的实体碰撞与本组件的点投影混为一项。此处“边滑”是源码步进规则，角色脚底与视觉遮挡的实际观感仍须在正式场景验证。

## W-02 纵深缩放

在 Potato 的 `Visual_TUNE` 挂 **Depth Scale**，**Ground Line** 指向已有基准线，**Local Config** 可空以读 Binder 的 Current，也可显式填 DepthScaleConfig。公式为 `因子=1+(groundLine.worldY−foot.worldY)×depthScaleFactor`，乘保存的 localScale，每帧从基准重算。默认 **Local Foot Offset**=(0,0,0)，pivot不在脚底时填缩放前本地脚底偏移；补偿只改视觉本对象的位置，父链比例不重写。k=0.03时脚底gl、gl+2、gl−2对应因子1、0.94、1.06，都是程序示例而非已保存场景结果。

**Use Override Factor** 默认为false，true时使用 **Override Factor**（系数、默认0.03/u，0有效）；否则依次尝试启用的 **Depth Override Provider** 和 Local Config/Current。`IDepthOverride` 仅预留系数接口，未提供区域实现。配置变化/Current换绑随生命周期订阅解绑；缺引用明确返回基准，不猜GroundLine。零/负因子保留，非有限输入不继续写NaN。Controller和Spine Avatar两处朝向均委托同一组件，保持公式符号及缩放幅度；停用移除自有纵深因子，未知外部改动保留。

完整字段、单位、操作、停用与限制说明见 [街景纵深缩放_配置与使用说明](../组件说明文档/视觉特效/街景纵深缩放_配置与使用说明.md)。ENGINE在已审V②接入后核三点脚底/缩放、临时空对象同组件与清理、真实朝向顺序、Console连续和作者clean；材质透明度、Ear及六部件和用户布局保持。USERa仍在W01/W02原生后调参，CODE离线结果不代签视觉。

## W-03 层内脚底Y排序

`YSorter`只改一个明确Renderer或SortingGroup的Order，Group引用优先；**Foot**必须显式绑定未受DepthScale视觉补偿影响的脚底根/锚点。公式为 `Base Order − round((foot.worldY + Depth Offset) × Precision_TUNE)`；**Base Order**默认0且为稳定手配值，不逐帧取目标输出；**Precision_TUNE**默认100 Order/u，0忽略Y；**Depth Offset**默认0u，正值偏后、负值偏前。round按双精度中间值就近、半数取偶数，结果饱和至−32768～32767；不改Sorting Layer ID或层名。

**Bake On Start**默认false，动态按脚底/参数变化重算；true时每启用/换目标仅采样一次，之后普通字段/位置变化需重启或工程Rebake才更新。停用只恢复仍自有的目标Order，外部Order/层ID改动优先；空目标/空脚底和非法输入不猜值。完整Inspector说明与六层E2映射见[街景层内排序_配置与使用说明](../组件说明文档/视觉特效/街景层内排序_配置与使用说明.md)。既有层名依次为LL_Background/LL_Buildings/LL_MidgroundBack/LL_Characters/LL_MidgroundFront/LL_Foreground，本卡不重命名。
