### V013-06 气泡纯逻辑消费（2026-11-16）

`Assets/Scripts/Narrative/Core/NarrativeAmbientBubbleModel.cs` 新增每NPC独立的取句/冷却模型；它没有Unity、真实输入、时钟、视图或命令处理器。本节只核源码/离线逻辑，不代表气泡已经显示。原配置默认、资产数值与字段定义保持，07后续才接触发/表现。

调用方给每个NPC保留唯一一个 `NarrativeAmbientBubbleModel(npcId, directory)`，目录是原INarrativeDataDirectory只读快照；`npcId`非空且保完整实例后缀。通过 `ChangePool(poolId)` 应用池；换成不同id清当前段/句和上次选段，保留该NPC上次成功触发的冷却截止时刻；重复应用同id不清进度。模型不承担“当前NPC应选哪个池”的状态策略，也不新建另一份目录/模型。目录快照在本模型生命期固定，场景/目录重建由外部管理。

先用原 `DialoguePresentationResolver.ResolveTrigger(config, triggerName)` 取trigger快照，再调用 `TryTrigger(nowSeconds, groundDistance, triggerSnapshot, chooseIndex, out emission)`。距离由外部GroundSpace等能力计算后传入，单位u；时间是外部单调秒数。必须严格 `groundDistance < autoBubbleRadius`，且 `nowSeconds >= CooldownUntilSeconds` 才成功；范围外、等于半径、冷却未结束都不前移句子或消耗随机。**气泡不使用 interactRadius。** 冷却从成功触发时起，按当次 `autoBubbleCooldown` 固定截止时间；之后改配置或换池不缩短既有截止时间。0半径不会触发，0冷却允许每次调用发一条，外部仍应按自己的帧/显示策略调用，不在模型里追加帧率门。

| 原trigger字段 | 原单位/默认 | 本模型消费及调节 |
| --- | --- | --- |
| autoBubbleRadius | u / 2.9 | 调大扩大允许范围，严格边界不变；不改变按键交谈范围 |
| autoBubbleCooldown | s / 10 | 调大发送更稀疏；只在下一次成功时采用新值，不改已有截止时间 |

取句沿原 `TryGetAmbientPool` / `TryGetDialogue` / `TryGetLineChain`：当前段未结束按链逐句，结束后在池的不同对话id中随机选段，多段时排除上一段，单段可以重复；重复引用同一id不伪装成第二段。`chooseIndex(candidateCount)` 是调用方提供的随机能力，需返回[0,candidateCount)整数，只在选新段时调用；续句不调用。无效返回值或外部随机异常不消耗冷却/句子进度。本模型不自动承接 `next_dialogue`，不走普通/剧情FSM。

结果 `NarrativeAmbientBubbleEmission` 提供NpcId/PoolId/DialogueId/LineId/TextKey/SpeakerId和成功/下次允许秒数。speaker非空就原样返回（含实例后缀），为空回到挂池NPC；不在Core找Transform、定位头顶或本地化文字。台词命令即便解析失败也不执行，只记录 `COMMANDS_IGNORED`，气泡正常；ambient的on_end也不执行并记录 `ON_END_IGNORED`。

空池、缺段/非ambient或链失败使整个池不触发，不靠随机跳过坏段；不会发链失败前缀。原链的非阻断标签诊断仍可发句并保留诊断。池解析结果随该不可变目录缓存，换池后重建；`Diagnostics` 为本NPC生命期只追加、按代码/池/上下文去重的只读集合，外部只消费新追加项，避免重复打印整个历史。诊断包括MISSING_POOL/EMPTY_POOL/MISSING_DIALOGUE/NOT_AMBIENT/INVALID_CHAIN、原链提示和无效输入/触发组/随机能力。拒绝不会启动冷却，也不会改正式表或默认值。

此为纯数据/逻辑消费，无新Inspector字段、显示组件或调试按钮。地面距离、随机来源、真实气泡位置/寿命/淡入退出和运行时状态接入仍待后继07/05，未作画面验收。

## C.4 站位：`data.layout[]` / PortraitLayoutConfig

`name` 初始default；`portraitBottomAlign` 初始true，表示设计上的屏幕底边对齐。`stations` 是人数到站位数组的内嵌表：每项 `actorCount` 为正整数，人数不能重复，`entries` 长度应与人数相同。每个站位的 `id` 为非空标识、同一人数集合内不重复，供后续cast_station选择；下列ID是开发期命名，不是导入的用户配置。

每个 `entries[]` 有 `id`、`position.x/y`、`scale`、`layer`。position是**显示锚点**相对屏幕底边中点的有符号px偏移，右/上为正；scale为非负倍率，增大立绘更大；layer为有符号整数，设计上高层在前。原图偏移先于缩放，缩放和说话者放大/上浮/平移都以显示锚点为中心，不以不透明图片底边或原图包围盒作轴。下半身不裁图，通过偏移放到屏幕外由屏幕边界自然截掉；本卡只存站位，没有实现这些绘制行为。

| --- | --- | --- | --- | --- |
| 1 | s1-center | (0,0) | 1 | 0 |
| 2 | s2-left / s2-right | (-747,0) / (747,0) | 各1 | 各0 |
| 3 | s3-left / s3-center / s3-right | (-853,0) / (0,0) / (853,0) | 各1 | 0 / 1 / 0 |

## 使用与排错

可先复制一个文字模板，将name设为slow、charsPerSecond设为20；这只是修改示例，未写入任何资产。`FindText("slow", out diagnostics)`返回该元素，错拼名称则给出诊断并回落default。修改位置时允许 `position.y=-100`，而 `portraitTime=-0.1` 会得到具体组/模板/字段错误，原值仍保留供人工处理。检验结果不替代未来表现验收。

资产通过Changed通知内容变化：OnEnable只记录基线；OnValidate比较序列化内容，内容相同不通知，首次无基线时只建立基线。代码修改Data中的字段后需调用NotifyChanged；该方法和Inspector比较依赖Unity的JsonUtility。ValidateData返回只读诊断，OnValidate同时输出警告，不自动修值。这些生命周期路径已真实DLL编译，尚未进行原生Inspector/序列化往返/通知验收。

数据对象是可变的配置编辑数据，Find返回原对象而非冻结副本；不要把它当作已经解析完成的每段演出快照。覆盖文本已经能解析为有类型值；覆盖优先级、值快照、表现、UI、控制锁与真实输入仍按后续任务接入。

## N0-07 参数 key、类型与覆盖文本

当前已提供 `DialogueParameterRegistry.Entries/TryGet` 和 `DialogueOverrideParser.Parse`。注册表读取原69个参数字段上的单位声明及真实字段类型，不保存另一套默认值。这里的key格式为 **`组.字段`**，大小写敏感；它对应上表的实际字段。例如 `data.text[0].autoWait` 的参数key为 `text.autoWait`，数组元素的name由后续模板选择负责。

组前缀固定为 `tier`、`trigger`、`entrance`、`layout`、`speaker`、`expression`、`text`、`reaction`、`cg`、`exit`。每组上表中的69个参数全部注册，包括触发等全局用途参数；模板name是选模板的身份字段。`entrance.order` 与 `exit.order`、`entrance.boxTime` 与 `exit.boxTime` 分别独立。`tier.commandExecutionMode`控制同句命令方式，entrance/exit的order用于入退场步骤，虽然复用枚举，职责不同。

注册项提供 `Key`、`Group`、`FieldName`、`ValueType`、`Kind`、`Unit`。单位标记为s、u、px、ratio、×、chars/s、bool、string、template-key、RGBA、px/×/layer或none；none表示枚举无物理单位。px基准仍为2560×1440，RGBA每分量[0,1]，站位的复合单位分别对应位置/缩放/层号。字段的单位声明是注册来源，实际数值约束仍复用N006校验。

覆盖集基本形式：

```text
text.charsPerSecond=24;tier.commandExecutionMode=Sequential;cg.kenBurnsPanX=-53;cg.kenBurnsPanY=20
```

key与赋值两侧可留空白；空/null/纯空白覆盖集表示无覆盖，末尾允许一个分号。中间空条目（如两个连续分号）、缺等号或空key会报告语法问题。CG横向和纵向各有独立key：`cg.kenBurnsPanX`、`cg.kenBurnsPanY`。

| 类型/Kind | 文本形式 | 解析结果与边界 |
| --- | --- | --- |
| 数值/Number | `1.25`、`1e-2`、`-53` | 实际Single，使用小数点，不随系统地区变化；有限性、非负/比例要求按对应原字段校验 |
| 布尔/Boolean | `true`、`false` | 实际Boolean，大小写不敏感；1/0或yes/no不是布尔值 |
| 枚举/Enum | `Parallel`、`ScalePop`等上表声明名 | 实际既有枚举类型，名称大小写精确；数值序号不作枚举文本 |
| 字符串/String | `hop`或`"hop"` | 裸文本去两端空白，引号内保留空白与分隔符；空值表示空字符串，不表示自动补default |
| 位置/Point | `(173,-173)` | 实际PresentationPoint，固定x、y顺序，允许有符号偏移 |
| 颜色/Color | `(0.5,0.5,0.5,1)` | 实际PresentationColor，固定r、g、b、a顺序，各分量[0,1] |
| 站位数组/Stations | 见下方 | 实际PortraitStationSet[]，包含人数、每个站位的ID/位置/缩放/层号 |

`cg.kenBurnsCurve`还接受Schema原拼写 `linear`、`quadratic`、`smooth_step`、`ease_in_out`，分别返回既有Linear、Quadratic、SmoothStep、EaseInOut。其余枚举按上表的实际名称，例如 `exit.continuationMode=Seamless`。

字符串含ASCII分号或双引号时，使用完整引号值：

```text
text.punctuationSet=";=，。！？";expression.expressionChangeTemplate="hop"
```

引号内支持 `\"`、`\\`、`\n`、`\r`、`\t` 五种转义，Unicode文字直接填写。未闭合引号、未知转义或引号后多余内容会报错。等号可作为字符串内容，分号只在引号外分隔赋值。

站位数组使用专用固定元组格式：

```text
layout.stations=[(2,[("left",-747,0,1,0),("right",747,0,1,0)])]
```

外层每项为 `(人数,[站位,...])`，站位为 `("id",x,y,scale,layer)`。ID必须加引号，也可用上述字符串转义；x/y为有符号px、scale非负、layer为有符号32位整数。人数为正整数、同组人数不重复，站位条数等于人数，单个人数集合中的ID非空且唯一。可写多个不同人数集合。`layout.stations=[]`沿用N006校验的合法空集合语义；它只表示新解析值为空，未修改原default中的四套站位。该固定格式只编码现有站位结构，没有引入通用序列化格式。

例如：

```text
expression.symbolOffset=(173,-173);trigger.markerTalkedTint=(0.5,0.5,0.5,1)
```

位置、颜色和站位均以原复合参数整体返回，内部各分量保留实际类型和字段含义。解析只产出值，不进行图片偏移、镜头漂移、布局或颜色处理。

### 诊断和结果使用

结果有 `Success`、`Values` 和 `Diagnostics`；每个成功值含真实注册定义及 `Value`。数值/布尔/枚举是各自实际类型，位置和颜色为纯结构体，站位数组为新创建的纯数据对象。列表只读，复合内容仍是可变编辑数据，冻结快照属于N008。

任何条目失败时，整体 `Success=false` 且 `Values` 为空，避免部分应用。每条诊断给出 `Key`、`Problem`、UTF-16文本位置 `Position` 和具体 `Reason`：

| 输入示例 | 问题 |
| --- | --- |
| `text.unknown=1` | UnknownKey：参数集合没有该key |
| `text.autoWait=wrong` | InvalidValue：需要有限数值 |
| `text.autoWait=-1` | InvalidValue：原字段要求非负，值不会被钳制 |
| `text.autoWait=1;text.autoWait=2` | DuplicateKey：同一key重复，整组失败，不采用最后值 |
| `text.autoWait=wrong;text.autoWait=2` | 同时保留首个值错误与重复诊断，不让第二条掩盖首错 |
| `layout.stations=[(1,[])]` | InvalidValue：指出entries条数与人数不符 |

解析器不接收用户模板或资产；约束核对仅在内部临时纯数据上复用N006校验，原默认、模板和配置资产不会被写回。原Parse入口继续只产出原子类型结果；N008另通过同源ParseItems取得逐项结果并冻结，见下章。当前仍无真实表现消费。

## N008 运行时优先级与只读快照

配置人员仍在原DialoguePresentationConfig的data十组模板中编辑，填写对话表九个profile列和overrides；本次没有新增Inspector字段、资产或场景绑定。每段按以下顺序生成独立快照：先取各组真实default；选中具名模板时用该组整套值替换（不是逐字段与default混合）；最后应用本段合法override。未知模板给出组/模板名诊断后回同组default。default缺失/重复、模板重名或原N006范围校验错误会使取值失败且无快照，不能靠override替用户修正配置或猜默认数据。

trigger没有对话表profile列。触发方可调用ResolveTrigger(data,templateName)单独取该组；它只检查trigger组配置，未知名同样给诊断并回default。完整Resolve(data,dialogue,triggerTemplateName)的第三项也是调用方给出，省略时取trigger的default。完整快照含十组/69参数，因此本段合法trigger覆盖也能生效；它不写回独立触发快照或影响其它段。

旧DialogueOverrideParser.Parse的协议保持：任一错误令Success=false、Values为空。N008通过同一词法/值解析的ParseItems逐项处理，保每项原文/位置及key、问题、原因，跳过错误项并继续应用独立合法项。例如text.autoWait=oops;cg.kenBurnsPanY=0中，autoWait保所选模板值且给诊断，PanY明确为0。不存在的key不会新建参数；类型/范围不符不会钳成默认。

重复按“首次出现保留key”处理：text.autoWait=1;text.autoWait=2应用第一项1，对第二项给DuplicateKey，不静默采用最后值。第一项若已经错，后续同key仍是重复，不能掩盖首错；其它不同key正常应用。分号/引号/转义完全沿原语法；未闭合引号会把剩余文本作为该错误项的尾部，不猜测引号内的分号来恢复条目。合法但含分号/等号的字符串仍须完整引号。本段取值Success可以为true同时有OverrideDiagnostics，表示成功生成“跳过错误项”的快照；配置致命错误则Success=false且Snapshot=null。

快照不是可编辑模板。参数点/颜色分别变成只读X/Y和R/G/B/A对象，站位变成只读人数集合/条目/位置，公开集合不能增删改。修改原配置、原解析的站位数组/盒装点色、下一段的override，均不会改变已经交付的快照。不得把取值结果写回模板或把一段快照当作下一段默认；每段从配置重新取值。

具体CG使用ResolveCg(dialogueSnapshot,cgModel)时，每一列单独处理：非空表值优先，空值回落本段已解析的CG组。横向/纵向漂移互不借值；0是有效显式值，false是有效显式关闭。例：本段CG组X=33、Y=44，表X=0、Y空，结果X=0、Y=44；表X空、Y=0则X=33、Y=0。其它时长/倍率/开关也按各自空值独立回落；曲线沿原Schema别名，未知CG模式/曲线给诊断而不猜默认。此入口只生成数据，不播放CG、计时或执行切场景。
