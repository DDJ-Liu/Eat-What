## 1. 在哪里配置

正式配置入口是 `Assets/Prefabs/Cooking/ShortCycle/FridgeCat/FridgeCat_Rig.prefab`：

- 选中根对象 **FridgeCat_Rig**，在 **Fridge Cat Rig**、**Fridge Cat Blink Scheduler**、**Sprite Outline Group 2D** 和 **Sprite Outline Merge Renderer 2D** 查看逻辑、眨眼和组级描边接线。
- 选中子对象 **ScrollController_TUNE**，在 **Scroll Area Controller** 配置内容根、拖动容器、视口边界、步进和程序过渡。
- `ShortCycle_P0P1/Spaces/Phase1_Kitchen/FridgeCat_Group/CatRig` 是源 Prefab 实例。层数、Tier 间距、Binder 槽位等正式 P0 覆写在这里核对；不要把源 Prefab 的 2 层默认值误写成 P0 的 6 层值。
- 场景 `FridgeCat_Group/ScrollRegion` 是固定的物理滚轮命中区，不属于 Prefab 移动内容，也不要移入 `VisualContent_TUNE`。

## 2. 当前层级与移动边界

保存态结构：

```text
FridgeCat_Rig
├─ ScrollController_TUNE                  固定
│  ├─ Viewport_TUNE                       固定边界
│  └─ ContentArea_TUNE                    运行时位移源
└─ VisualContent_TUNE                     保存态 identity，运行时挂到 ContentArea_TUNE
   ├─ HeadAndTopTiers                     头身与前两层
   ├─ Eye_L / Eye_R                       嵌套眼睛 Prefab
   ├─ Base_Feet / Ear_L / Ear_R
   ├─ Arm_Raised / Tail
   ├─ Tiers                               P0 Tier_03~06 与后续池化层
   ├─ Deco_Lines                          猫本体线条装饰；随同一内容根移动
   ├─ FridgeCat_Rig_MergedShadow          合并阴影显示宿主
   └─ FridgeCat_Rig_MergedOutline         合并描边显示宿主
```

`VisualContent_TUNE` 的保存态 Local Position/Rotation/Scale 必须为 `(0,0,0)` / identity / `(1,1,1)`。`ScrollArea_Controller.Initialize()` 会用保持世界姿态的方式把它重挂到 `ContentArea_TUNE`；之后分页只移动 `ContentArea_TUNE`，整猫视觉自然继承同一位移。

固定对象包括 Rig 根、`ScrollController_TUNE`、`Viewport_TUNE` 和场景 `ScrollRegion`。不要把整个 `CatRig` 指给 `content`，因为 `ContentArea_TUNE` 是它的后代，会形成祖先循环。也不要只把 `HeadAndTopTiers` 塞回 `Tiers`，这会混淆前两层与扩展层的所有权。

## 5. Anchor 对齐与自动边界模式

**Anchor Aligned Auto Bounds** 不使用固定世界坐标、相机 X、固定 5/6 层或固定 30 槽。`SetTierCount()` 会从当前有效层的代表 Anchor、固定 Viewport 边界和 `ContentArea_TUNE` 的实际 `lossyScale.y` 推导纵向可移动范围：

- 当前层归一化位置：`(首层 Anchor Y - 当前层 Anchor Y) / (首层 Anchor Y - 末层 Anchor Y)`；所以固定层与扩展层间距不同时，相邻页不再强制等分。
- Content Collider 世界高度：`Viewport 世界高度 + 首末 Anchor 世界跨度`；再除以 `abs(ContentArea.lossyScale.y)` 得到 Collider 本地高度。
- Collider Y Offset 会被求解为：归一化 0 时首层 Anchor 恰好落到 **Tier Alignment Target TUNE**，归一化 1 时末层 Anchor 落到同一条固定线。
- 只改 `ContentArea_TUNE` 的 BoxCollider2D 高度和 Y Offset，X 尺寸/Offset、Viewport、ScrollRegion 和 `VisualContent_TUNE` 所有权不变。数值没有变化时不重复写 Collider，也不会在滚动时分配新对象。
- 0 层不滚动；1 层不除零且行程为 0；6→2→6 与 6→8→6 会按当前有效首末 Anchor 重算边界，扩展层仍复用既有池。

配置前置条件：ScrollArea 必须是 Vertical，Content Drag Container 必须以 BoxCollider2D 为尺寸源，Viewport/Content/Target 引用完整，代表列 Anchor 必须从上到下严格递减。首次启用时建议把固定 Target 放到玩家应看到的层线，并在正式初始化前完成配置；若要保持 Tier0 首次显示不跳，Target Y 应与稳定旧基线中 Tier0 代表 Anchor 的实际落点一致，而不是凭截图手填常量。
