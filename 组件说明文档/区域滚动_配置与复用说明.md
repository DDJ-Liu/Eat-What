## Unity 6 滚轮手感配置

正式配置入口是 `DataTables/Cooking/CookingGameConfig.csv`，不是场景里保存的旧 Inspector 数值。F4 导入后，`ShortCycleSessionManager` 在启动时读取 T8 并调用 `MouseManager.ConfigureScrollInput`。Inspector 的 **Mouse Wheel Scroll** 分组仍可观察实际运行值和状态，但不应作为正式手感配置源。

| T8 key / Inspector 显示 | 默认值 | 单位、范围及调节效果 |
| --- | --- | --- |
| `fridge_scroll_threshold` / **Scroll Threshold** | 1 | Input System 统一滚轮单位，必须大于 0。改小更敏感，改大需要更多小幅输入累计。缺失、非 invariant-culture 数字、NaN/Infinity、零或负数都回退为 1，并输出明确诊断。 |
| `fridge_scroll_cooldown` / **Scroll Cooldown** | 0.2 | 秒，必须大于等于 0，使用不受 timeScale 影响的时间。改小会更快连续翻页，改大更慢。缺失、非 invariant-culture 数字、NaN/Infinity 或负数都回退为 0.2，并输出明确诊断。 |
| **Accumulated Scroll / Last Scroll Time** | 运行时状态 | 用于诊断，不是手感配置入口；重启组件、换目标/输入层或失焦会重置。 |

例如维持 Threshold=1、Cooldown=0.2：一个归一化值为 1 的完整滚轮刻度立即产生一步；连续五次 0.2 的细小脉冲累计为一步。冷却期间最多保留一步，时间到后执行。因此快速连拨后停手可能先立即走一页、冷却到期再走一页；每次派发仍是一页，但不等于每组连拨只走一页。离开目标、切输入层、禁用组件或失焦时清除待执行输入，重新命中后从新手势开始。输入反向时会先清除旧方向余量，再累计新方向。

本次没有调整全局 Input System 设置，也没有改方向、分页间距或序列化场景。**Last Raw Scroll Y** 与累计阈值现在采用同一 Input System 单位，不再进行平台条件换算。配置文本始终按 invariant culture 解析，小数必须使用点号（例如 `0.2`）。`fridge_scroll_granularity` 和 `fridge_scroll_damping` 已从当前 CSV/schema 契约删除；F4 导入时还必须确认旧生成资产和 Catalog 引用没有残留。

## 1. 能力边界

`ScrollArea_Controller` 是通用区域滚动组件。它只负责：

- 把一个内容根挂到可移动的 `DragContainer` 下；
- 根据固定 `DragLimit` 计算可移动边界；
- 将 0～1 的归一化目标换算成世界位置；
- 接收连续或离散滚轮步进；
- 可选使用 Position Transition 做平滑程序滚动；
- 同步 ScrollBar 和位置变化事件。

它不依赖菜谱、库存、冰箱层数、`ShortCycleSessionManager` 或 `ActionRouter`。普通列表、说明页、图鉴等内容都应优先复用这个组件。

冰箱是另一种接法：物理滚轮先经 `ShortCycleScrollAdapter` 映射，再进入业务 Action、Session、Binder 和 Rig，最终由 Rig 调 `ScrollArea_Controller.ScrollVerticalTo`。这个桥负责阶段门控和“下一层/上一层”，不是通用 ScrollArea 的必需组件。

## 2. 普通内容对象的必要结构

建议层级：

```text
ScrollRegion                         固定命中区，可选
└─ MouseScrollableObject            物理滚轮事件源，可选

ScrollController                    固定控制器
├─ ScrollArea_Controller
├─ TransitionBehaviour_Position     可选；target 指向 ContentArea
├─ Viewport                         固定可视边界
│  └─ DragLimit                     建议 Inner 边界
└─ ContentArea                      唯一移动节点
   ├─ DragContainer
   ├─ MouseDraggableObject          需要拖拽时才接
   └─ ContentRoot                   实际内容；Initialize 时保持世界姿态重挂进来
```

`ScrollArea_Controller` 的最低必要接线：

| Inspector 字段 | 必填 | 含义 |
| --- | --- | --- |
| **Scroll Mode** | 是 | Vertical、Horizontal 或 Composite。 |
| **Content Drag Container** | 是 | `ContentArea` 上的 `DragContainer`，是真正移动的节点。 |
| **Content** | 建议 | 实际内容根；初始化时会用 `SetParent(..., true)` 保持世界姿态重挂。不能是 `ContentArea` 的祖先，否则会形成父子循环。 |
| **Viewport Drag Limit** | 是 | 固定视口上的 `DragLimit`，`Initialize()` 用它刷新边界。 |
| **Content Draggable** | 否 | 需要鼠标拖拽时接；不影响程序滚动。 |
| **Content Scrollable** | 否 | 兼容字段；滚轮是否工作取决于 `MouseScrollableObject.scrollStepEvent` 的实际 UnityEvent 接线。 |
| **Vertical/Horizontal Scroll Bar** | 否 | 只做显示/外部控制；初始化会关闭 ScrollBar 自带滚轮，避免重复输入。 |
| **Scroll Position Transition** | 否 | 不接时即时落点；接入时目标必须是 `ContentArea`。 |

普通区域需要物理滚轮时，可以把目标 `MouseScrollableObject.scrollStepEvent(float)` 直接接到 `ScrollArea_Controller.OnScrollStep(float)`。同一个物理事件不要再同时接业务 Adapter，否则会一次输入移动两次。

## 3. 坐标、单位与方向

### 3.1 归一化位置

`ScrollTo(Vector2)`、`ScrollVerticalTo(float)` 和 `ScrollHorizontalTo(float)` 的输入单位都是归一化比例，合法范围 0～1，超出时自动钳制：

| 轴 | normalized=0 | normalized=1 |
| --- | --- | --- |
| Y | `LimitMinY` | `LimitMaxY` |
| X | `LimitMaxX` | `LimitMinX` |

X 轴反向是“内容向左移动以展示右侧内容”的既有显示合同，不等于物理滚轮翻转。

### 3.2 滚轮步进

`OnScrollStep(direction)` 使用 `current - direction * step`：

- **Continuous**：step 为 **Scroll Step**，默认 0.05，Inspector 范围 0.01～0.2；
- **Discrete**：step 为 **Step Size**，默认 0.5，Inspector 范围 0.01～1；
- direction=0 不移动；正负输入都会先按当前模式计算，再钳制到 0～1；
- 达到上下/左右边界后继续同向输入不会越界。

这里的 direction 是传给 ScrollArea 的输入符号。通用组件不猜测鼠标硬件“滚轮向上/向下”应代表什么业务含义。

### 3.3 冰箱的单点方向映射

正式冰箱路径是：

```text
MouseManager
→ MouseScrollableObject.scrollStepEvent
→ ShortCycleScrollAdapter.MapPhysicalStep
→ Dispatch
→ ActionRouter → Session → Binder → FridgeCatRig
→ ScrollArea_Controller.ScrollVerticalTo
```

- `MouseManager` 达到阈值后只发物理 `+1/-1`，全局符号不能为单一场景改写；
- **Invert Physical Scroll Direction** 只影响 `MapPhysicalStep`；关闭时保留符号，开启时只翻一次；
- `Dispatch(+1)` 始终表示下一层，`Dispatch(-1)` 始终表示上一层，直接调用 `Dispatch` 不受反转开关影响；
- 正式 P0 当前保存态为开启，且只在 `Spaces/Phase1_Kitchen/FridgeCat_Group/ScrollRegion` 上开启；AI139 的 SIMULATED 物理事件回归得到 `raw -1→+1`、`raw +1→-1`，没有改共享输入符号或业务方向；
- `FridgeScrollLab` 的 SIMULATED 入口直接调用 `Dispatch`，因此保持同一业务语义；REAL_INPUT 才经过物理映射。Lab 当前未序列化该新增字段、按代码默认值等价关闭，继续作为独立参考基线，不因正式场景配置而同步。

## 4. 初始化与生命周期

- **Manual Initialize=关闭**（默认）：`Start()` 自动调用 `Initialize()`。
- **Manual Initialize=开启**：宿主必须显式调用 `Initialize()`；在此之前不会建立父级或刷新边界。
- 初始化前调用 `ScrollTo` 时，只缓存最新一个归一化请求；成功初始化并 `UpdateBounds()` 后同步应用一次。无请求或重复初始化不会重复移动。
- Controller 与 Position Transition 宿主都 active/enabled 时，程序滚动走平滑 `PlayTo`；任一宿主 inactive、Transition 缺失或无法启动时，直接同步落到同一目标。
- 新请求会替换旧过渡；禁用或销毁时只把最新目标完成一次，避免遗留协程或重复回调；重新启用后可继续发新请求。
- `onScrollPositionChanged(Vector2)` 的单位仍是归一化 0～1。手动拖动时应把 `DragContainer.onDragPositionChanged` 接到 `OnContentPositionChanged`，用于同步 ScrollBar 与事件。

## 5. 配置示例

### 普通纵向说明页

1. `Scroll Mode=Vertical`，`Step Mode=Discrete`，`Step Size=0.25`。
2. `Content Drag Container=ContentArea`，`Content=ContentRoot`，`Viewport Drag Limit=Viewport`。
3. 把 `ScrollRegion/MouseScrollableObject.scrollStepEvent` 只接到 `ScrollController/ScrollArea_Controller.OnScrollStep`。
4. 需要平滑时给同一固定 `ScrollController` 增加 Position Transition，目标指向 `ContentArea`；不需要时留空。
5. 在实际父级缩放和最终内容尺寸下执行初始化，再验证 0、1、连续正负步进、两端钳制、禁用/启用和重复初始化。

### 冰箱分层

不要把物理事件直接接到 `ScrollArea_Controller.OnScrollStep`。应保持既有 `ScrollRegion → ShortCycleScrollAdapter → ActionRouter → Session → Binder → Rig` 单一路由，由 Rig 根据层 Anchor 计算目标。详细字段见[冰箱猫整体滚动：配置与使用说明](视觉特效/冰箱猫整体滚动_配置与使用说明.md)。

## 6. 常见错误与限制

- 不要同时直连 ScrollArea 和业务 Adapter；否则一格物理输入可能产生两次移动。
- 不要为单个场景改共享 `MouseManager` 的符号，也不要颠倒 `ScrollArea_Controller` 的 0～1 数学。
- `Content` 不能是 `ContentArea` 的祖先；移动节点、固定 Viewport 和物理命中区必须分开。
- 边界取决于最终 Collider/Rect、父级世界缩放和 `DragLimit`；编辑器外桩不能替代真实 Unity 父变换验证。
- ScrollArea 不处理业务锁、容量、层数、选菜状态或 Modal；需要这些语义时通过业务桥接，不把依赖塞回通用组件。
- 本文确认的是代码、正式场景配置和 SIMULATED 机器合同。真实鼠标方向、Game View 焦点进入/离开、视觉速度和手感仍必须在目标场景 Play Mode 人工验收；不得把程序调用 UnityEvent 或 `Dispatch` 写成 REAL_INPUT。
