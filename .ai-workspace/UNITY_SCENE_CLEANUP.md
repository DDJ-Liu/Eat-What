# Unity 验证现场的归属与自动清理

2026-09-15制定。用户明确要求：MCP管线自己的操作使场景变脏，应自行修复清理，不应重复提交人工审批。此规则适用于已获准任务的现场恢复，不自动启动手动模式任务，不代替视觉验收，也不扩大生产修改范围。

## 执行顺序

1. 开始场景操作前记录目标Editor、加载场景路径/GUID、Edit/Play/Compile状态、各场景dirty、任务独占情况、磁盘scene/meta SHA及必要对象原值。已有用户未保存修改不得直接保存、丢弃或用磁盘备份代替内存保护；仅在不影响它的隔离范围继续工作。
2. 生产修改按审定字段保存并核对差异；将已确认的保存版本设为本轮验证恢复点。备份与日志放在Assets外。执行Play、强制TMP网格更新、临时相机/探针、截图或审计前，登记本批可能产生的临时对象/字段、恢复动作及所属任务，记录前后dirty。只读审计避免ForceMeshUpdate、SetDirty等会改变对象的调用；需要强制更新时按临时变更登记。
3. 在工具调用的可见说明中同时写明本次验证及收尾清理范围：目标路径、已保存恢复点、临时对象、已知归属和用户授权。临时Camera/RT/材质/探针用try/finally恢复原引用并释放；需要跨工具调用的Play测试，在任务记录中列出Stop和恢复步骤。不得因截图把临时证据默认导入Assets。
4. 退出Play后等待稳定Edit，核对磁盘哈希、对象/序列化变化及临时对象。满足“基线明确、测试期间由本任务独占、没有用户/其它任务插入修改、当前变化均有本轮操作记录、恢复点包含所有应保留成果”时，自动恢复本任务临时字段，或通过Unity Editor/MCP重新加载该已保存场景。这是用户已授权的验证收尾，不新增人工闸门。多场景情况下只处理获准目标，不隐式关闭或丢弃其它场景。
5. 临时资产只在证明由本任务创建、无业务引用、已有Assets外证据副本后，用AssetDatabase清理精确路径及其meta；禁止通配或删除未知目录内容。重新读取场景和关键字段，确认持久diff仍符合范围、Console无新增错误、临时对象/RT已释放，并记录清理前后dirty。若可重复的运行组件在重载后立即再次标脏，记录触发组件/时机，安排最小代码修复；不要无限重复重载。

## 判定与升级

- `scene.isDirty`或`EditorUtility.IsDirty`只说明有变更标记，不证明存在应保存的产品修改，也不证明可以丢弃。TMP/Renderer类型、对象数量或磁盘副本哈希一致，单独都不是全部内存变化归属的证据。
- 已确认属于本任务的临时脏状态：记`RecordIssue`及恢复结果，自动清理后继续。不要转成产品验收项，也不单凭dirty调用GLOBAL Fail。
- 无法确认归属、基线前已有未保存变更、外部插入修改或超出审定diff：先保全、定位并继续不受影响工作；只有必要恢复会覆盖未知成果、无安全替代时才停相关操作并请用户处理。确有跨任务风险时依原GLOBAL规则停派发。
- 不用MarkSceneClean/ClearDirty掩盖尚未核对的变化，不为清除星号把整份未知内存状态覆盖保存到正式场景。审计副本与磁盘同SHA不能代替当前内存差异核对。
- 平台自动审批仍独立生效。若实际被拒，按返回原因处理；补充只读证据或更安全方案可以继续，禁止改API、关安全检查或换命令绕过同一拒绝。明确用户续做授权到来后可按原任务协议恢复，保留错误史。

## 收尾证据最小表

### AI132 补充：当前副本与单资产恢复

- Dynamic 字体在验证期间可能正常增字；字符/图集哈希变化不是损坏证明。记录字符增减、图集/材质引用和实际文字来源，区分正式内容与夹具文字。测试用非生产文字的字体副作用应在执行前登记；需要运行期副本隔离时，先验证副本及资源释放，不直接永久切换生产字体模式。
- 对受保护资产恢复前，既保存已交付恢复点，也另存**当前** asset/meta 并验证哈希。MCP 恢复请求显式给出两个版本的路径、哈希、保留内容及用户既有清理授权；不能只写“按文档回滚”，也不能拿写前备份替代当前现场保全。
- 字体恢复、场景重载、遗留 meta 清理分别处理；每一步完成后再决定下一步，避免一次请求同时覆盖生产资产和删除文件。当前副本可保全且无须删除的遗留文件先保留。此拆分用于缩小影响、提供实际保全，不用于绕过已拒绝操作。
- 正式文字若必然再次补字，先核对必要字符与字体契约，技术修正后建立新的明确恢复点；不通过无限重载/回滚追逐旧哈希。资源恢复后再核真实字体状态下的回归，旧截图不冒充恢复后的证据。

### AI127/129 补充：TMP 副作用与多场景测试隔离

- 测试前另存当前已交付字体及 meta 的精确恢复点，区分写前旧版本与最新交付版本。TMP 激活/刷新可改变内存材质引用，Dynamic 补字也可能在后续场景保存时落盘；所以既要核场景 diff，也要核字体字符表/图集和文件哈希。不能为了去掉 dirty 标记而反复保存正式场景。
- 非加法切换若因未知未保存内容被平台拒绝，停止该丢弃动作。保留原场景的加法加载只有在确实不丢弃、不覆盖原内容时才是更安全的替代；不得借另一 API 达成被拒绝的丢弃。原始拒绝及新的安全依据必须留证。
- 加法打开第二个验证场景不等于建立了独立测试环境。Play 前检查所有已加载场景中的 InputManager、MouseManager、EventSystem、Camera、AudioListener 和 Session 等唯一服务；两个完整业务场景同时启动产生的重复单例、OnDisable 异常或视图混合不能靠清空 Console 算作生产回归通过。
- 优先先确认额外测试场景已保存、clean 且无用户修改，再通过 MCP 关闭该精确测试场景，只保留本轮目标场景进行正常 Session 验证。临时禁用/隔离方案也必须明确所有权、恢复表和实例选取依据，且不能掩盖正式场景真实问题。若新的关闭/清理仍被实际拒绝，按该次理由停止或提供实质更安全方案，不重复等价尝试。
- 报告分别列“日志历史”“清理后空闲 Console”“单场景从初始化开始的完整回归”，保留此前异常原文。六层可达需实际截图和现有交互层的命中证据，Renderer/Anchor 坐标进入相机仅是必要条件，不能代替遮挡、裁切与实际命中验证。

任务/Editor/场景；写前是否干净；保存恢复点SHA；临时操作及变化归属；是否有外部插入；恢复动作；恢复后关键字段/dirty/Console/资源释放；剩余问题。dirty计数按采样时间记，不能当作恒定删除清单。
