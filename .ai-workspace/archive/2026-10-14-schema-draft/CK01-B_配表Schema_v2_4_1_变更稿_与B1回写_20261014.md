## 二、裁决算法（写入 Schema §P2 运行时规格 S-02）

```
输入：recipeId, areaId, itemId（被拖入食材），scene carriers（分区内实际厨具）
1. records = T12 中 input 含 itemId 且 action ∈ T14[areaId].allowed_actions 的记录
2. records = records ∩ T1[recipeId].whitelist_proc_ids（保持白名单顺序）
3. candidates = records 映射到承载物类型，并与分区实际厨具取交集（去重，保持首次出现顺序）
4. 若 candidates.Count == 0 → 走"白名单内无命中"（不明物体 / 拒绝，既有规则）
5. 若 candidates.Count == 1 → 命中
6. 若 candidates.Count > 1 → 取 candidates[0]（即白名单首条）；触发 R-01 warning
```
不读 preset_tools；不读场景对象顺序；不新增 priority 字段。

## 四、B1 回写文本（v2.1.1 → v2.1.2，设计 chat 执行）

**4.4 多候选承载物的裁决**（替换原段）
> 同一分区、同一激活食材在白名单内推出多个承载物时，首要手段仍是策划在 `T1.whitelist_proc_ids` 上手动收敛。收敛后仍出现多候选的，按**白名单列表顺序取第一条在本分区可命中的处理记录**所隐含的承载物；该情况定性为配置缺陷：校验器 V-09 给出 warning，运行时在 Console 以 `[CK01-S02]` 提示一次，无 UI 表现。分区厨具的来源为场景内实际摆放的厨具（`SceneToolIdentity`），`T14.preset_tools` 自 v2.4.1 起废弃。

**4.5 分区与承载物来源**（新增一句）
> 分区可用承载物 = 场景内该分区实际厨具 ∩ 白名单隐含承载物；`allowed_carriers` 仅作校验与限制集合，由场景清单同步，不再作为预载配置。

**第十四章语义映射表**：`T14 KitchenAreas（core_facility / preset_tools）` → `T14 KitchenAreas（core_facility / allowed_carriers·来源=场景）`；"demo 洞洞板阉割期承载物来源=preset_tools" → "来源=场景厨具清单（AI188）"。

**变更记录**：v2.1.2 2026-10-14：4.4 兜底改白名单顺序（G74）；4.5 承载物来源改场景；preset_tools 废弃；T3 两列正式化。
