## 二、工作区与流程规则（现行，指向根文档）

- 五条车道：CODE / ENGINE_MCP / ART_AIGC / **ART**（资产审查同步，日审 `ART-DAILY-YYYYMMDD` 不占编号）/ ART_ASSET；部署入引擎一律 ENGINE_MCP。
- 模式：MANUAL（只记录/编排，不派发）/ SUPERVISED（按依赖与资源锁自动接力，人工统一后置）；切换由用户显式声明。
- **人工审查统一后置**（2026-09-10）：机器门过即续段，人工在开发末尾统一进行。
- **PERMISSION 来源=B**：安全门只认执行流水线窗口内的用户直接消息；指令内授权块只能减少询问，不能替代。凡覆盖/删除/改名已部署资产、改序列化场景字段、改 Prefab/ProjectSettings/字体，用户须在窗口本人批准。
- `CloseWithoutAcceptance`：无独立人工观察路径的配表/源码交付可行政关闭（终态 CLOSED_WITHOUT_ACCEPTANCE，不等于人工通过）。
- 美术导入：先逐文件识别/比对/最终路径命名草案，用户审核后正式导入；不经 ArtImports 中转。视觉改动先进统一 Lab。
- Editor 脚本：CODE 任务产出 `Assets/Editor/**` 后链尾追加 ENGINE Compile-only 步（P-036/P-038）。
- 授权块格式：路径 / 动作（删除·新建·重设父级·修改字段·覆盖·改名·保存）/ 范围 / 备份 / 保持不变；SHA 未知写"以领取时为准并在报告记录"。
- 工具登记：先查 `TOOLKIT_REGISTRY`，新建/扩充/更名/弃用回写；完成门槛六要素含"工具登记影响"（手册 C7）。
- G26：验证辅助代码（探针、驱动器、LayoutAudit、runner、两 Lab）不删不降级；冲突时 VERIFY-TEMP 标注。
- 坑账本现至 P-045（控制台维护）；设计端自记：P-030 拆聚合类必附"职责→归属→触发点"表；P-035 探针一步激活；P-036 stub runner ≠ Editor 编译。

- **单工作区**：所有任务只面向 `D:/GameProject/Eat-What`。迁移副本仅为 E2 前的保留物，不是第二条开发线。
- **字体保护持续有效**：`ShortCycle_Heavy_WithFallback` 有提交前 SHA 保护（基线 `1D379A…399CC2`）。它是动态图集，Play 或构建时渲染到新字符就会被写回磁盘——迁移期间已发生三次。现行处理：发现漂移即经 Editor 整份恢复，**不提交**。派发涉及新中文文案的任务时须预期此保护会触发（结构性解法见 §十 建议项）。
- **Unity 资源安全规则持续有效**：不手改 YAML；场景/Prefab/资产的变更一律经 Editor 或其 API 保存；未知差异先看 diff，不直接丢弃；`.meta` 允许由 Unity 在经审定目录正常生成。
- **TMP 目录已入库**（`Assets/TextMesh Pro/`，字体与 SDF 走 Git LFS）：各机器须装好 Git LFS；本地原先被忽略的同名目录在 checkout 时会被仓库版本覆盖，属预期。
- **MCP**：Coplay 包已入库于 `LocalPackages/com.coplaydev.unity-mcp/`（上游固定提交，10 个本地补丁禁止其自动改写客户端配置），manifest 用工程内相对路径；服务端按入库的 uv.lock 恢复，同机只启一个 localhost:8080 服务。恢复与路由步骤见 `DevTools/MCP/README.md`。
- **保护哈希的跨目录限制**：场景/TMP 的 SHA 基线按工作目录字节计算，受各 clone 行尾转换影响，同一提交在不同目录的原始 SHA 可能不同；当前以"Git 规范化后一致"为准，原目录哈希由开发端另存（改进建议见 §十）。
- **E2 之前仍保留的临时物**：迁移副本、E 盘异盘备份、`.ai-workspace/outputs/control/MIG63_执行_20260921/` 本地证据（未入库，E2 时统一归档）、带批次名的长期工具与资产（E2 时按功能改名）。
