## 6. 队列与追踪机制（`[USER]` 伪车道已落定 G64；额度治理 G71）

- INSTRUCTIONS 中人工项以 `USER-U1~U6` 登记：有 dependsOn、有状态（PENDING_USER_WORK / DONE），**不派发、不占 AI 编号**；AI 支撑任务 dependsOn 对应 USER 项。
- 追踪表 v1.2「人工工作项」表由你填"完成日期"；控制台每日日报（ART 日审同机制）读该表状态，人工项 DONE 才解锁后置 AI 任务。
- 代码波次开工条件：F 收口 + E2 完成 + 对应 U 项 DONE；未 DONE 的人工项由你决定是否放行。
- 额度治理（G71）：每批次规划与每轮收口时，设计端复核 usage 周报（首份 2026-09-30）、根文档体积、MCP 返回体 Top5、任务粒度、验证/报告体量；趋势上升即提调整。

### 6.1 人工项状态的更新方式（G64，2026-09-22 已落定）
- **权威源是工程内文件**：`.ai-workspace/inputs/USER_WORK_STATUS.md`（常驻输入，随分支入库），一张表：`编号 | 人工工作 | 状态(TODO/DOING/DONE/BLOCKED) | 完成日期 | 备注`，初始由我给出 U1~U6 行。你在本地编辑器改状态即可，随内容分支提交。
- **控制台命令是快捷方式**：在派发 chat 发 `USER-U1 DONE 2026-09-2x` 或 `USER-U2 DOING`，控制台把同一行写进该文件并回显；两种方式最终落到同一文件，不并存两套状态。
- **读取**：日报心跳（同 ART 日审机制）每日 00:00 读该文件；AI 支撑任务领取前预检 dependsOn 的 USER 项是否 DONE，未 DONE 则不领取（不熔断，只等待）。
- 追踪表 Excel 的「人工工作项」表是**你的阅读视图**，不是权威源；每版由 USER_WORK_STATUS + 主本生成。
