## 1. 总体架构需求

### 1.1 空间与画面关系
- Phase 0 与 Phase 1 同场景连续空间，镜头平移切换。空间布局：左半边 = Phase 1 厨房（冰箱猫+线索板壳+托盘备菜区），中间 = Phase 0 食谱本，右半边 = 旁支系统预留空位。
- Phase 1 → Phase 2 为画面/场景切换（接受跳变）。本批次做到"触发切换+数据交接"为止。
- 旧工程 6 个 Cinemachine vcam 均为静态构图点（Follow/LookAt=null），可作机位参考；镜头平移控制器需新建。MouseInteractionLayer 栈式输入分层沿用。

### 1.2 状态体系
Phase 0：**⓪封面**（前置画面，点击翻开进①）/ ①主浏览页（默认，双页：左详情、右留空预留图鉴收集）/ ③目录页（双页 8 卡镜像，demo 不翻页留接口）/ ④线索板展开 / ⑤步骤详情页（全屏遮罩弹窗）。
Phase 1：⑥a1/a2/a3 冰箱滚动视野 / ⑥b1 托盘备菜区三态（G13）/ ⑥b2 步骤详情叠加（复用⑤组件）。

### 1.3 运行时上下文
- 跨阶段长期状态：InventoryManager（全新建）、PlayerProfile（全新建，含收藏）、KitchenEquipmentManager（占位）、PlayerUnlockManager（demo 全解锁桩）。
- ShortCycleContext：current_recipe_id、trigger_context、is_mismatch_dish、prep_zone_contents、placeholder_states、current_filter_tag、current_scroll_offset、current_phase。
- 运行时结构定名参照 schema v2 第四节（含 StepCompletionState）。
- 资源消耗铁律：Phase 0/1 零真实数据变更；全部变更集中在 Phase 1→2 统一数据处理一次执行。

### 1.4 退出层级
- Phase 0 是唯一退出层：ESC → FreeTry 直接退出、清上下文、回上游占位画面；其他触发来源仅留确认弹窗接口。
- Phase 1 返回箭头 = 回 Phase 0（状态全保留），不是退出。

## 3. Phase 1 功能需求

### 3.1 冰箱猫面板（新黑猫资产，参考图1）
- 猫身即格架（zhutu 内建 3 层板）；格位=格架上独立点位 + 格件 prefab（结构件+图标+名称标签+角标+占位符态+拖拽/悬停组件）。滚动=格架内容滚动+猫身拉长（拆段：头/可重复中段/脚，**拆段资产待补**；补齐前可视 3 层 15 格、容量 20 需滚动）。眼光层 yanguang 接眨眼调度。
- 每格下挂食材名称标签（T4.name_key，接标签自适应字号）。
- 容量：**按 T10 FridgeCapacityLevels 档位表配置（20/30/40/50/60 五档），demo 运行时固定取 lv1=20**；升级流程挂起，读表机制先行。
- 排列：紧密无空隙；新食材最前；筛选后紧密重排。
- 双区滚动：默认滚轮→冰箱；线索板区滚轮→线索板（板挂起期可不接内容）。颗粒度/阻尼走 T8 参数，人工段实调回写。
