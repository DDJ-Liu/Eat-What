### V015-10 · 立绘导入方式的核对与告警 [DATA · 工具链]

| 项 | 内容 |

| 对应 | 本版新增（1.3） |

**为什么有这张卡**：用户放进 `Assets/Sprites/Narrative/Portraits/` 的五张立绘（`Octopus`、`Pomegranate-1`、`Pomegranate-2`、`Potato`、`Tomato`）都是"多张子图"的导入方式；其中 `Potato` 的导入设置里登记了 `Potato_0`、`Potato_1` 两块。用户 11-21 确认：`Potato` 就是一张图。也就是说，这两块是切片切出来的，不是两张立绘。现行的《剧情资源目录方案》要求立绘能按文件路径取到一张完整的图，多图切片不接——这条约定不变；图的导入方式由 V015-18 改成单张。本卡负责把事实核对清楚，并让导表在遇到这种文件时把话说明白。

**执行前**：按 2.7，先跑一次数据表工具链的导入约定入口和发布数据包的离线入口，报告结果。

**内容**
1. 核对并报告（读导入设置文件与图片文件头，不需要开引擎）：

| 核对什么 | 用来做什么 |
|---|---|
| 五个文件各自的导入方式、切了几块、每块的名字与矩形；图片本身的宽高 | V015-18 的依据；V015-11 算初始缩放要用图片的高度 |
| 工程里有没有别的资产引用了这五张图里的某一块 | 有引用的话，V015-18 改导入方式会让引用失效，要先报告 |
| 有没有预设或导入后处理脚本，把这个目录下新放进来的图片默认设成"多张子图" | 有的话写明是哪一个。不改它，由用户决定 |

2. 规则不变，写清楚：`portrait_sprite` 一格填文件基名，区分大小写，不带路径与扩展名；这个文件必须是单张导入。不按子图的名字引用，不取多张子图里的某一块。
3. 导表与静态校验（V-18 的"立绘图按资源契约存在"）遇到导入方式是多张子图的立绘文件：告警，文字写明"这张立绘的导入方式是多张子图，请改为单张"，这个角色当作没有立绘。现有的行为已经是"取不到并告警"时，只把告警的文字改清楚并补测试；不是的话才改读取，改动限于读取立绘的那一段。
4. CG 与立绘共用同一段读取时一起生效，在报告里写明。
5. 更新《剧情资源目录方案》：立绘与 CG 的导入方式写明为单张；多张子图的文件会告警、不接。

**新行为与原有断言**：告警的文字变了。断言里比对这条告警原文的，跟着改，在报告里逐条点名。别的原断言不改。

**不做**：不改图的导入设置（V015-18 做）；不做按子图名取图（表情差分属于完整版）。

**验收（逻辑与数据）**：夹具——单张导入的图：取到；多张子图切了一块的、切了两块的：都取不到，告警文字正确；同一份设置重复读取结果相同。正式 22 张表校验 0 错误，告警数与 47 条相比的变化逐条说明。真实导入在 V015-13 执行，取到的图由 V015-16 按 id 核对。回归门见 2.7。

### 2.3 立绘怎么摆（Schema 共同约定 A 的实现口径）

| 项 | 口径 |
|---|---|
| 显示锚点 | 屏幕上的一个点，相对屏幕底边中点，2560×1440 基准下的像素，向右、向上为正 |
| 对准点 | 立绘图上对到显示锚点的那个点：横向 = 0.5 + 偏移 x，纵向 = 偏移 y，都是相对图片的比例（0 到 1）。比例相对整张图片，含透明留白 |
| 大小 | 缩放为 1 时，图片的 1 个像素等于基准分辨率的 1 个像素 |
| 缩放 | 站位的缩放 × 角色表的缩放 × 本段的缩放。留空按 1 |
| 顺序 | 先对准，后缩放。缩放、说话者的放大与位移，都以显示锚点为中心 |
| 下半身 | 不裁切。靠纵向偏移把下半身放到屏幕底边以下 |
| 在哪一侧 | 显示锚点的横向位置大于 0 是右，小于 0 是左，等于 0 是中 |

有三处是对 Schema 的补充，不算与它冲突（用户 11-21 已确认，回写见 7.3）：约定 A 写"角色表的缩放与对话表的缩放相乘"，工程里的站位表另有一个缩放字段，这里三者相乘；默认站位的"出场人数"只算有立绘的人；显示锚点在屏幕中线右边的立绘默认水平镜像。

### 2.4 画面的层次

不变。立绘放在对话界面 Prefab 里已有的立绘层，在压暗层之上、对话框之下。

### 2.5 状态机的事实（V015-04、05 按它来写）

出场名单、说话者、场景反应这几个请求，在状态机里没有等待完成的回报口。收到就开始做，不回报。出字不等立绘，立绘的渐变也不等出字。入场、退场仍然按 0.1.4 的约定，等那一次调用返回之后再回报。

### 2.6 禁止

对话的纯逻辑程序集里出现引擎类型；对话系统引用 LongLoop 或短循环；改状态机、调度器、推进输入模型、取值器的既有行为；改镜头代码；改气泡、头顶标记、按键提示、操作锁、已聊过记录的行为；除 V015-08 写明的那一处外改主角控制器；除 V015-18 写明的那一项外改立绘的导入设置；改立绘的文件名或图片本身；往演出配置里加参数，或改用户已保存的参数值；改对话界面 Prefab 里已有节点的布局值；修改 T1~T23 的定义；改正式表里已有的非空格；为了通过而修改既有测试的断言；新写探针、守卫、比较器；使用已冻结的验证探针。
