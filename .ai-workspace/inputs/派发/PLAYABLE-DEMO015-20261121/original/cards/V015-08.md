### V015-08 · 街上的场景反应 [CODE]

| 项 | 内容 |
|---|---|
| 对应 | 追踪表 PRS-9 |
| 所属模块 | LongLoop |
| 状态所有者 | 规则的一次运行归本组件（V015-03 的规则在里面） |
| 规模 / 纯洁度 | 中 / B |
| 前置 | V015-03、V015-07 |

**组件放哪、谁来接线**：一个场景一个，放在街景里对话服务所在的那个对象上（V015-13 接线）。**不挂在 NPC 上**。NPC 经现有的目标注册表取，预摆的和按状态生成的都已经在里面，不需要逐个接线。

**流程对照**

| 步 | 什么时候 | 做什么 | 与前一步的关系 | 实现位置 |
|---|---|---|---|---|
| 1 | 服务通知一次对话的第一段开始 | 取这段的 `turnMode`、`turnDelay`；找出发起对话的 NPC；把它和主角的横向位置交给规则；按规则的结果设两者的朝向 | 立即 | 本组件 |
| 2 | 服务通知"一句开始" | 找出说话者在街上的小人，交给规则 | 立即 | 本组件 |
| 3 | 每帧 | 把时间交给规则；规则计时到点、要候选名单时，给出注册表里每个在场 NPC 的横向位置、是否在屏幕内、现在的朝向；按规则的结果设朝向 | 第 2 步之后持续 | 本组件 |
| 4 | 整次对话结束，或被中止 | 按规则给的恢复清单设回朝向 | 立即 | 本组件 |
| 5 | 续接的下一段开始 | 只重新取 `turnMode`、`turnDelay`，不重做第 1 步，不恢复 | — | 本组件 |

**怎么找、怎么判**

| 项 | 做法 |
|---|---|
| 发起对话的 NPC | 沿用 0.1.4 里"发起对话的 NPC 不冒新气泡"所用的来源 `[核]`。没有现成的来源时，由交互选择器与调试面板在开始对话之前把发起的 NPC 告诉本组件；不改对话服务开始对话的入口 |
| 说话者在街上的小人 | 说话者与发起对话的 NPC 是同一个角色（不看多实例后缀）→ 就是发起的那个。否则按角色 id 在目标索引里精确找（不带后缀）。主角的角色 id 找到的是主角。找不到 → 没有小人 |
| 是否在屏幕内 | NPC 的脚底点在街景相机此刻的可见范围之内。相机按引用接入，不搜索主相机 |
| 现在的朝向、设朝向 | 用壳现有的设朝向入口。壳上读不到当前朝向时 `[核]`，加一个只读的取值 |
| 取值 | `turnMode`、`turnDelay` 来自 V015-07 的快照查询 |
| 时间 | 与对话服务用同一种不受时间缩放影响的时间 |

**主角的朝向**：主角控制器加一个入口——"朝向左或右"，只改朝向，不移动；走控制器现在改朝向的同一条路 `[核]`，纵深缩放的配合不变；操作锁锁住时也有效。这是本包里唯一允许改主角控制器的地方，只由本组件在第 1 步调用。

**新行为与原有约定**：0.1.4 的操作锁说明里写着"锁住时外部不另写主角的位置或朝向"，人工检查里有一项"锁住后主角停下，朝向与位置保持"。本卡之后改为：位置保持；朝向在对话开始时转向对方一次，之后保持。操作锁拦的是设备输入，这条规则没有变，主角原有的 99 项断言预期都不受影响。哪一条因为新入口而不成立，停下来报告，点出是哪一条。说明文档里的那两句由 V015-15 改。

**不做**：反应图标；对话途中场景状态被切换时的处理（0.2.2 才有切换状态的命令）。

没有接服务、注册表或相机时，本组件不工作，记一次诊断，不报错。

**验收（逻辑与数据）**：单测，用假的服务通知、假的注册表、假的相机范围——对话开始时两者的朝向；说话者的小人三种找法（同角色的发起者、按 id 精确找到的、主角）；找不到时不转；屏幕内外的判断；延迟到点后被设朝向的是哪些；对话结束后恢复的是哪些，主角不在其中；续接时不恢复、不重做互相面对；中止；`turnMode` 为不转身；缺引用时不工作。主角的新入口：左、右各一次；锁住时有效；不产生位移。转身实际看起来的样子交人工。回归门见 2.7。

### 2.3 立绘怎么摆（Schema 共同约定 A 的实现口径）

| 项 | 口径 |
|---|---|
| 显示锚点 | 屏幕上的一个点，相对屏幕底边中点，2560×1440 基准下的像素，向右、向上为正 |
| 对准点 | 立绘图上对到显示锚点的那个点：横向 = 0.5 + 偏移 x，纵向 = 偏移 y，都是相对图片的比例（0 到 1）。比例相对整张图片，含透明留白 |
| 大小 | 缩放为 1 时，图片的 1 个像素等于基准分辨率的 1 个像素 |
| 缩放 | 站位的缩放 × 角色表的缩放 × 本段的缩放。留空按 1 |
| 顺序 | 先对准，后缩放。缩放、说话者的放大与位移，都以显示锚点为中心 |
| 下半身 | 不裁切。靠纵向偏移把下半身放到屏幕底边以下 |
| 在哪一侧 | 显示锚点的横向位置大于 0 是右，小于 0 是左，等于 0 是中 |

有三处是对 Schema 的补充，不算与它冲突（用户 11-21 已确认，回写见 7.3）：约定 A 写"角色表的缩放与对话表的缩放相乘"，工程里的站位表另有一个缩放字段，这里三者相乘；默认站位的"出场人数"只算有立绘的人；显示锚点在屏幕中线右边的立绘默认水平镜像。

### 2.4 画面的层次

不变。立绘放在对话界面 Prefab 里已有的立绘层，在压暗层之上、对话框之下。

### 2.5 状态机的事实（V015-04、05 按它来写）

出场名单、说话者、场景反应这几个请求，在状态机里没有等待完成的回报口。收到就开始做，不回报。出字不等立绘，立绘的渐变也不等出字。入场、退场仍然按 0.1.4 的约定，等那一次调用返回之后再回报。

### 2.6 禁止

对话的纯逻辑程序集里出现引擎类型；对话系统引用 LongLoop 或短循环；改状态机、调度器、推进输入模型、取值器的既有行为；改镜头代码；改气泡、头顶标记、按键提示、操作锁、已聊过记录的行为；除 V015-08 写明的那一处外改主角控制器；除 V015-18 写明的那一项外改立绘的导入设置；改立绘的文件名或图片本身；往演出配置里加参数，或改用户已保存的参数值；改对话界面 Prefab 里已有节点的布局值；修改 T1~T23 的定义；改正式表里已有的非空格；为了通过而修改既有测试的断言；新写探针、守卫、比较器；使用已冻结的验证探针。

发现本包与 Schema v2.5.3 或现行代码冲突，停驻上报。
