# 派发包索引 · 可玩包体 demo-0.1.5 对话有人像 · v1.1-index（2026-11-21）

> **v1.1：按用户 2026-11-21 对细则的裁决改写，见第六节。v1 没有投放，由本版整体替换。**相对 v1 的改动：立绘改为单张导入（V015-10 改写，新增 V015-18）；没有立绘的人不算出场人数（V015-01）；右侧立绘默认镜像（V015-04）；章鱼给主角、石榴给对话专用角色，占位对话重新分工（V015-11、14、16）；人工检查底稿随之改写。

### 2.2 状态的唯一所有者

| 状态 | 所有者 |
|---|---|
| 一段对话里每个出场的人站在哪、多大、谁在前 | 站位解析的结果（V015-01）。一段开始时算一次，之后不变，由舞台持有 |

| 立绘调参的临时值 | 舞台上的临时覆盖表（V015-04）。只在编辑器与开发构建里存在 |

### 2.3 立绘怎么摆（Schema 共同约定 A 的实现口径）

| 项 | 口径 |
|---|---|
| 显示锚点 | 屏幕上的一个点，相对屏幕底边中点，2560×1440 基准下的像素，向右、向上为正 |
| 对准点 | 立绘图上对到显示锚点的那个点：横向 = 0.5 + 偏移 x，纵向 = 偏移 y，都是相对图片的比例（0 到 1）。比例相对整张图片，含透明留白 |
| 大小 | 缩放为 1 时，图片的 1 个像素等于基准分辨率的 1 个像素 |
| 缩放 | 站位的缩放 × 角色表的缩放 × 本段的缩放。留空按 1 |
| 顺序 | 先对准，后缩放。缩放、说话者的放大与位移，都以显示锚点为中心 |
| 下半身 | 不裁切。靠纵向偏移把下半身放到屏幕底边以下 |
| 在哪一侧 | 显示锚点的横向位置大于 0 是右，小于 0 是左，等于 0 是中 |

有三处是对 Schema 的补充，不算与它冲突（用户 11-21 已确认，回写见 7.3）：约定 A 写"角色表的缩放与对话表的缩放相乘"，工程里的站位表另有一个缩放字段，这里三者相乘；默认站位的"出场人数"只算有立绘的人；显示锚点在屏幕中线右边的立绘默认水平镜像。

### 2.4 画面的层次

不变。立绘放在对话界面 Prefab 里已有的立绘层，在压暗层之上、对话框之下。

### 2.5 状态机的事实（V015-04、05 按它来写）

出场名单、说话者、场景反应这几个请求，在状态机里没有等待完成的回报口。收到就开始做，不回报。出字不等立绘，立绘的渐变也不等出字。入场、退场仍然按 0.1.4 的约定，等那一次调用返回之后再回报。

### 2.6 禁止

对话的纯逻辑程序集里出现引擎类型；对话系统引用 LongLoop 或短循环；改状态机、调度器、推进输入模型、取值器的既有行为；改镜头代码；改气泡、头顶标记、按键提示、操作锁、已聊过记录的行为；除 V015-08 写明的那一处外改主角控制器；除 V015-18 写明的那一项外改立绘的导入设置；改立绘的文件名或图片本身；往演出配置里加参数，或改用户已保存的参数值；改对话界面 Prefab 里已有节点的布局值；修改 T1~T23 的定义；改正式表里已有的非空格；为了通过而修改既有测试的断言；新写探针、守卫、比较器；使用已冻结的验证探针。

发现本包与 Schema v2.5.3 或现行代码冲突，停驻上报。

### 6.2 由这次裁决带出来、我定了写法的五处

裁决说了方向，落到卡上还差几个具体的点。已按下表写进卡里；不合适告诉我编号。

| # | 写法 | 理由 |
|---|---|---|
| 1 | **五张立绘由一张引擎操作卡（V015-18）改成"单张"导入，需要你授权。**只改导入方式这一项，图片本身、文件名、别的导入设置都不动。以后新放进来的立绘也要选单张；选成多张子图的，导表会告警、这张图接不进来 | "两张子图"说的不是两个图片文件，而是 `Potato.png` 的导入设置：它的导入方式是"多张子图"，里面登记了 `Potato_0`、`Potato_1` 两块切片（0.1.4 报告里开发端核对出来的）。这通常是自动切片把图里不相连的两部分各切成了一块。既然它就是一张图，取其中一块只会显示半张，所以不能按 v1 的"取第一张"做；改成单张才是整张图。另一个好处：两张 `Pomegranate` 改成单张后落在同一张画布上，以后做差分切换不会跳位置。**你更愿意自己改也可以**：在 Unity 里选中这五张图，把导入方式改成单张再应用，然后告诉开发端跳过 V015-18 的第 3 步 |
| 2 | `Pomegranate-1` 给了对话专用角色（人四） | 它是街上最干净的测试对象：不冒气泡，五句台词里有旁白、有主角。借给谁只影响占位，改角色表的一格就能换 |
| 3 | **表情差分本版不做。**`Pomegranate-2` 改成单张导入后留在目录里，不绑给任何角色，登记为差分的测试素材 | 设计文档把表情差分标在完整版。要做的话得先定三件事：角色表里差分一列怎么写、台词表里表情一列怎么读、切换时怎么过渡。**如果你的意思是 0.1.5 就要能切差分，告诉我**，我先把这三件事的写法给你过目，再补卡 |
| 4 | 没有立绘的人在名单里等于不在：不占位置；轮到他说话时，立绘全部变灰，名字框在左 | 裁决的直接推论。校验本来就会对这种配置告警 |
| 5 | 主角有了立绘之后，占位对话重新分了工：`dlg_test_talk_a` 改成"NPC 在左、主角在右"的两人对话；验单人站位的换成土豆那一句；验"没有名单就没有立绘"的换成人一二号那两段 | 主角有立绘而不在名单里，校验会告警；NPC 与主角一左一右也是以后最常见的配置，放在最干净的对象上验 |
