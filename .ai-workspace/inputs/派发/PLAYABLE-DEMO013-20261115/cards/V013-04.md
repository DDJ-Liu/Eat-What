> 来源：派发包_可玩包体0_1_3_v1（2026-11-15）第四节；单卡文件。数据结构以随包的《CK01-B 配表 Schema v2.5.1》为准。标 [核] 处按现行代码核对；发现冲突停驻上报。

### V013-04 · 运行时接入点 [CODE]

| 项 | 内容 |
|---|---|
| 对应 | 新增 |
| 所属模块 | 对话的 Unity 侧程序集 |
| 状态所有者 | 不持有业务状态；只持有对配置资产和数据的引用 |
| 规模 / 纯洁度 | 小 / B（新组件加 LongLoop 的程序集引用） |
| 前置 | V013-01 |

**内容**
1. 一个场景里的接入组件：引用演出配置资产；提供数据目录（经底座批的适配层 `[核]`）和取值器。
2. 街道代码只通过它拿配置和数据，不自己去找资产。
3. 数据从哪里读，沿用现有的数据源接口：编辑器与开发构建读生成的数据，发布构建读加密数据包 `[核]`。本卡不改数据源本身。
4. LongLoop 的程序集定义加上对两个对话程序集的引用。
5. 配置资产或数据缺失时，给出明确的诊断，接入点报告"不可用"；依赖它的组件据此不工作，不抛异常。

**验收（逻辑与数据）**：单测——有配置有数据时能取到目录与触发分组的参数；缺配置、缺数据各自报告不可用；LongLoop 加引用后离线编译通过。回归门见 2.5。

## 二、结构与硬约束

### 2.1 代码放哪

| 内容 | 位置 | 说明 |
|---|---|---|
| 气泡的取句与触发规则 | 对话的纯逻辑程序集 | 不引用引擎 |
| 气泡视图、运行时接入点 | 对话的 Unity 侧程序集 | 不引用 LongLoop |
| 演出目标索引、通用 NPC 的壳、场景状态应用、气泡的触发组件、调试入口 | LongLoop | LongLoop 新增对两个对话程序集的引用 |

对话系统不引用 LongLoop。需要街道提供的能力（主角的地面位置、角色头顶的挂点）通过接口传入。

### 2.2 状态的唯一所有者

| 状态 | 所有者 |
|---|---|
| 场景里有哪些角色、锚点 | 演出目标索引（V013-02） |
| 每个 NPC 在不在场、在哪个锚点、朝向、用哪个形象、挂哪个气泡池 | 场景状态应用器（V013-05）。它写入，别人不写 |
| NPC 自身的位置、朝向、当前形象子对象 | NPC 的壳（V013-03） |
| 每个 NPC 的气泡冷却、当前池里播到哪一段哪一句 | 气泡的触发组件，逻辑在 V013-06 |
| 屏幕上的每个气泡 | 气泡视图（V013-07） |

### 2.3 取值顺序（Schema v2.5.1 共同约定 B，本版只涉及形象与气泡池）

| 配表里的值 | 实例自身的值 | 结果 |
|---|---|---|
| 填了 | 任意 | 用配表的 |
| 留空，或没有这个角色的条目 | 有 | 用实例自身的 |
| 留空 | 没有 | 没有（无形象 / 不冒气泡） |

"实例自身的形象"指实例的形象挂载点下已经存在的子对象；"实例自身的气泡池"指触发组件上保存的池 id。

### 2.4 禁止

对话的纯逻辑程序集里出现引擎类型；对话系统引用 LongLoop 或短循环；修改 0.1.2 镜头代码的行为、主角控制器与主角形象组件；修改 T1~T15 的定义与数据；往正式表里写占位内容以外的行；为了通过而修改既有测试的断言；新写探针、守卫、比较器；使用已冻结的验证探针。

发现本包与 Schema v2.5.1 或现行代码冲突，停驻上报。

### 2.5 回归门：只有下面这些入口，逐个点名

| 入口 | 基线为绿的依据 | 哪些卡要跑 |
|---|---|---|
| 对话系统的离线入口 | 底座批收口时全部通过（11-15） | V013-04、06、07 |
| 街道代码的离线入口，只跑这四个模式：默认、纵深缩放、层内排序、地面距离 | 底座批曲线卡续行时全部通过（11-14） | V013-02、03、05、08 |

写法统一为：这些入口的**原断言**不改并通过。街道镜头的其余模式、短循环的入口不作门，不要求跑。执行前发现上表某个入口在当前基线上已经是红的，先报告，不在本卡里修。
