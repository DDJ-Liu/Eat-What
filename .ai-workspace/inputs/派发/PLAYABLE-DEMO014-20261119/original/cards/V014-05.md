### V014-05 · 对话界面层与场景压暗 [CODE]

| 项 | 内容 |
|---|---|
| 对应 | 追踪表 PRS-1、PRS-8 |
| 所属模块 | 对话的 Unity 侧程序集 |
| 状态所有者 | 场景压暗的当前量归压暗件 |
| 规模 / 纯洁度 | 中 / B |
| 前置 | 无 |

**内容**
1. 界面层：一个屏幕空间的画布根，基准 2560×1440，按高度缩放（与气泡画布一致），不随镜头的移动与缩放变化。下面分三层：压暗层、立绘层（本版为空）、对话框层。整体排在气泡画布之上，各层次序见 2.4。
2. 压暗件：一块铺满屏幕的黑色，透明度从 0 到指定的量。能做的事：提出一个压暗请求（目标量、过渡时长）；撤销这个请求（过渡时长）。同时存在多个请求时取最大的量。
3. 过渡中途又来了请求或撤销：从当前的量接着走，不跳变。
4. 压暗量取自快照的 `normalDim`；时长由调用方给。
5. 压暗层不拦截点击。
6. 只负责压暗。虚化本版不做，留出接口位；不承担黑幕过渡。
7. 字体沿用气泡现在用的字体资产 `[核]`，不改字体资产。
8. 结构上要能整体放进任何一个场景，由 V014-18 做成 Prefab。

**验收（逻辑与数据）**：单测——一个请求在给定时长内从当前量走到目标量；两个请求取最大；撤销后回落；过渡中途再请求不跳变。表现交人工。回归门见 2.7。

|---|---|---|

### 2.5 状态机的回报约定（V014-07、08、09 都要遵守）

状态机向视图发出一个请求的那次调用里，视图不能直接回头调状态机。即使是立刻就完成的事——时长为 0、步骤被去掉、本版不支持的请求——也要等这次调用返回之后再回报。回报时带上状态机当时给的那个关联对象，过期的不报 `[核]`。

对话的纯逻辑程序集里出现引擎类型；对话系统引用 LongLoop 或短循环；改状态机、调度器、推进输入模型、取值器的既有行为；除 V014-11 写明的那一处外改镜头代码的行为；除 V014-10 写明的那一处外改主角控制器；改主角的形象组件；改气泡的显示逻辑；往演出配置里加参数，或改用户已保存的参数值；修改 T1~T23 的定义；往正式表里写本包列明之外的行；为了通过而修改既有测试的断言（V014-11 写明的夹具调整除外）；新写探针、守卫、比较器；使用已冻结的验证探针。
