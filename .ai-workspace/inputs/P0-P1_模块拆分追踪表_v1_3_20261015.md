# P0-P1 需求模块拆分与功能块追踪表 · v1.3（2026-10-15，并入 P2 拆分表 v1）

> 用途：以后每段开发只认领本表的功能块（或条目），进度按六列状态更新；任务号、G 决策号、TK 登记号互相引用。
> 三层：模块 M（Space 级）→ 功能块 B（一个 Binder / 交互组 / 子状态机）→ 需求条目 R（B1/F2-a 可指到节的最小可验收行为）。编号 `M<n>-B<n>-R<n>`。
> **优先级（v1.1 新增）**：`P1 主链路`=没有它，"封面→选菜→看食谱→进 P1 备菜→进 P2 做出一道菜"的逻辑走不通（数据/状态/交接）；`P2 必要反馈`=主链路能走但玩家看不懂或无反馈（必要 UI、视觉表现、错误提示、占位/堆叠/高亮）；`P3 细节优化`=动画、手感、装饰、可选功能（翻页、耳臂尾、筛选整理、收藏、释义）。开发顺序：P1 全部通过 → P2 → P3；同优先级内按模块顺序。`主链序` 列仅对 P1 且未完成条目编 A/B/C 波次（A 食谱本最小绑定 / B 托盘拖放主链 / C 进入 P2 与最小闭环），见《开发路径规划 v1》。
> **v1.2 新增列**：`人工前置`=该条目开发前需用户完成的人工工作（`配表` 正式配表内容 / `排布` 引擎内 `_TUNE` 位置与参数 / `配表+排布` / `无`）；MIG63 并行期（S→E1，G52 代码冻结）优先完成全部"配表"与"排布"前置，见《开发路径规划 v2》。

**追踪规则**
1. 认领以功能块 B 为单位；一条链只改一个 B 的状态列，跨 B 影响写在报告"影响块"。
2. 状态列只允许上表七个词；"通过"必须带 AI 号或"09-17 一揽子"。
3. 新需求先加 R 行再派任务；设计文档改动先改 B1/F2-a 再改本表"设计"列。
4. 本表每轮结束由设计端更新一版（v1 → v1.x），与总档同批；Excel 由主本生成同版。
5. 任务指令必须引用条目编号（`M?-B?-R?`），报告"影响块"列出跨块条目；控制台按编号回写"验收"列草稿，设计端定稿。
6. 优先级只由设计端改；优先级是**派发选择的参考序**而非硬门槛（G80）：默认先派 P1，但当用户给出的前置限制把高优先级条目筛掉时，可派的低优先级条目即成为待选；P2/P3 条目派发须在任务卡注明"优先级越级"原因。
