# 美术资产校验规则

> 状态：草案；正式自动校验和自动部署均未启用  
> 当前例外：2026-08-17 已授权一次“备菜界面视觉原型”导出。仅限已登记的三类 PNG，必须先经 Error 级预检、不得覆盖同名不同内容的既有资产，并生成独立报告；不替换现有玩法逻辑、Prefab 引用或正式资源。  
> 当前冻结原因：本轮重新导出的 UI 尺寸已写入 JSON `pending_constants`，但仍需美术确认其为最终尺寸规范  
> 定位：工程入口校验规则——只审查从美术端导出、准备进入 Unity 工程的最终资产。美术端源文件维护（PSD、色板、基准线、完成度分级）不属于本文档范畴。  
> 配套机器可读定义：`ArtAssetValidationRules.draft.json`

## 1. 严重级别定义

| 级别 | 行为 |
| --- | --- |
| Error | 阻止自动部署。修复后重试，或按第 7 节豁免结构显式登记豁免。 |
| Warning | 保留在待确认队列，不自动部署，人工裁决后放行或退回。 |
| Info | 记录进检查报告，不阻止。 |

所有规则均有唯一 ID，按域分组：`FILE`（文件准入）、`NAME`（命名）、`SIZE`（尺寸）、`PATH`（落盘路径）、`DUP`（重复）、`IMPORT`（Unity 导入设置）。豁免、升降级和报告均引用规则 ID。

## 2. 命名体系

以拼音命名体系为权威规范：`<类型前缀>_<语义标识>.png`。

- 旧英文体系命名（`ingredient_*`、`recipe_image_*`）为合法既存例外：校验器放行并标记 Info（NAME-005）；是否迁移待程序端确认（NAME-PENDING-01）。
- 文件名与配表 uid 的关联校验为可选增强项，需在“语义标识 → 配表 uid”映射表建立后启用（NAME-PENDING-02），不作为当前强规则。
- 新交付资产不得主动沿用旧英文体系例外。

## 3. 强规则（Error）

| ID | 规则 |
| --- | --- |
| FILE-001 | 同步区中的实际交付物只接受非空 PNG。零字节文件、非 PNG 位图一律拒绝。 |
| FILE-002 | PSD 及其他源文件格式出现在同步区即为 Error。报错应提示“请导出 PNG 后交付，源文件不入工程”。 |
| FILE-003 | 系统垃圾文件（`Thumbs.db`、`.DS_Store`、`desktop.ini`、`__MACOSX/`）自动忽略，不计入交付物，不报错。 |
| FILE-004 | “命名示例”类零字节说明文件仅作目录说明，不进入 `Assets`；出现在部署清单中即为 Error。 |
| NAME-001 | 文件名格式为 `<类型前缀>_<语义标识>.png`，只使用小写拼音/英文、数字和单下划线。 |
| NAME-002 | 禁止中文、空格、连字符、全角标点、连续下划线和大写字母。 |
| NAME-003 | 同批次内或与 `Assets` 既有文件仅大小写不同的文件名即为 Error。 |
| SIZE-001 | PNG 必须含 Alpha 通道。 |
| SIZE-002 | 任一边不得超过 8192 像素。 |
| DUP-001 | 同批次内相对路径不得重复。 |
| PATH-001 | 交付物必须落入第 5 节分类表已确认的路径；未登记类别的资产必须先登记类别。 |

## 6. Unity 导入 preset

当前三个类别暂共用 `cooking_single_sprite` preset；后续类别可以单独定义。IMPORT-001 以对应 preset 为校验基准：

```yaml
preset: cooking_single_sprite
textureType: Sprite
spriteMode: Single
sRGB: true
alphaIsTransparency: true
mipmaps: false
readable: false
nPOTScale: None
wrapMode: Clamp
maxTextureSize: 2048 # SPEC-001 可能按类别覆盖为 4096
pixelsPerUnit: 100
filterMode: Bilinear
meshType: FullRect # 当前三类资产需为 Alpha 描边保留完整透明画布
compression: Normal
```

Point 过滤、特殊 PPU、Full Rect 等例外只能按用途登记于豁免表，不由文件名自动推断。

### 6.1 备菜视觉原型构图约束（临时）

- 设计分辨率：`2560×1440`；PPU：100；正交相机 Size：7.2；世界可见范围：`25.6×14.4`。
- 使用 URP `PixelPerfectCamera` 的 2560×1440 Reference Resolution 与 Windowbox，避免其他屏幕比例改变构图范围。
- 冰箱猫等宽或高非 2 次幂的交付素材在原型中保持 `Transform Scale = 1`；`512×512` 食材/菜品图标允许按 Alpha 可见区域缩放。
- 当前原型统一使用 `#30231F`、6 源图片像素的外框描边；颜色和 0～32 像素粗细由根节点 `SpriteOutlineGroup2D` 调整。
- 需要描边的 Sprite 必须使用 Full Rect；若原图有效像素贴近画布边缘，仍需美术保留足够透明边距，避免外框在纹理边缘被截断。
- 本节只约束当前可追溯视觉原型，不代表最终尺寸规范已获批准，也不解除草案冻结状态。

## 7. 豁免结构

豁免必须结构化登记于 JSON `exemptions` 数组，缺少任一字段即为无效：

```yaml
rule_id: 被豁免的规则 ID
pattern: 文件 glob 匹配模式
reason: 豁免理由
approved_by: 批准人
expires: YYYY-MM-DD 或 permanent
```

`permanent` 需要主策与程序双批准。到期豁免自动失效，并在下一批次报告中提示清理。

## 9. 定稿与接入路径

1. 美术确认本轮重新导出的 UI 尺寸是否为最终规范。
2. 第 8 节悬挂事项逐项裁决，填充所有 `{PENDING:*}`。
3. 已确认 Warning 按裁决升级为 Error 或登记豁免。
4. 规则定稿升为 v1.0 后，再启用自动流程：读取同步变更清单 → 只校验 Added/Updated → 合格后复制到第 5 节路径。

在以上步骤完成前，本草案不得作为正式准入标准执行。上述视觉原型导出是一次受限例外，不改变此结论。

## 10. 批次报告约定

正式启用后，每次批次校验生成独立报告 `ValidationReport_<date>.md`，包含：文件盘点、按规则 ID 的命中清单、Warning 待裁决队列、生效豁免和到期提示。

盘点数据只进入批次报告，不写回本规则文档。
